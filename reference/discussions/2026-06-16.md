## Granularité du write : tous les combien de frames ?

**Aden :** « on fait un writing step tous les combien de frames concretement ? »

**Réponse (vérifié code) :** **1 write par bloc de `num_frame_per_block` = 3 frames latentes**. Le write (`ttt_update=True`) se déclenche une seule fois par bloc, sur la passe propre (`causal_inference.py:237`, le re-run à timestep ~0, comme l'update KV-cache). Read à chaque pas de débruitage (4x), write 1x/bloc. En durée : ~0.75 s de vidéo par write. 5s=7 writes, 10s=14, 120s=~160, 240s=~320. Lien VRAM : clip 24->1 write backpropé, 27->2, 30->3, 33->4.

## q/k/v : par bloc ou par token ?

**Aden :** « c est des matrices de query de taille dim*3 pour les 3 frames et qui cree une query une key par serie de 3 frames ? »

**Réponse (corrigé sur le code) :** Non. Un bloc de 3 frames = **L = 3 x frame_seqlen ≈ 3 x 1560 = 4680 tokens**. Le qkv sort **une q, une k, une v par token** (chacune de head_dim ; num_heads=1 -> head_dim=dim=1536). Donc 4680 queries/keys/values par bloc, pas une. Ce qui est "1 par bloc" c'est l'**update des fast-weights W=(w0,w1,w2)** : le write agrège les 4680 paires (k_i,v_i) en UN seul pas Hebbian (somme de produits extérieurs) + Newton-Schulz + weight-norm. Image juste : un bloc de 3 frames = un **mini-batch de 4680 paires** pour un pas de montée de gradient sur la mémoire. (Le dim*3 vu dans `self.proj` = le shift/scale/gate du gating de sortie, sans rapport avec les 3 frames.)

## Colloque Yu Sun (fondateur du TTT) -- ce qui compte pour nous

**Aden :** « I put in the md colloquium, it was a colloquium about test time training by one of the founder of the concept, can you check if there is anything important in it »

Direction concrète : drop le terme gradient-of-gradient à travers Muon/NS = first-order TTT.

2. **"Practice the right skill" = E1 vs E3.** (≈L335-339) *"if you just practice regular tests during training, you're practicing the **wrong skill**... practice **take-home tests** = learning to learn = meta-learning."* -> E1 (write no_grad, on entraîne la lecture seule) = mauvaise compétence ; E3 (write dans le graphe) = la vraie. 3. **TTT-Video = notre prior art, nommé.** (≈L877-885) one-minute video, dynamic motion, depuis un storyboard, one-shot, "first model early 2025". = papier TTT-Video (Dalal, Sun). Eux = TTT teacher-forced ; notre nouveauté = write à travers le **self-rollout** causal. Confirme la note de nouveauté.

4. **Motivation identique.** Self-attn KV-cache coût linéaire -> sliding window borne le coût mais **oublie** hors fenêtre -> loss remonte ; TTT compresse le contexte évincé dans les poids. = Anchor-Forcing (local attn sink+window) oublie -> drift d'identité -> MAG compresse. "Holy grail = plat sur latence ET loss" = notre argument. Réutilisable tel quel en intro.
